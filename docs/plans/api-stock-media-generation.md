# План генерации карточек товаров, изображений и видео через API Stock

## Цель

Добавить в Modern Admin единый серверный контур генерации медиа через API Stock. Первый пользовательский сценарий — создать изображение карточки товара из полей записи, просмотреть результат и только после явного подтверждения сохранить его в поле товара. Тот же контур должен поддерживать произвольные изображения и видео без передачи API-ключа в браузер.

Официальный контракт, на который опирается план:

- [каталог и схемы моделей](https://docs.api-stock.com/en/docs/api/catalog);
- [создание генерации](https://docs.api-stock.com/en/docs/api/generation);
- [статус задачи](https://docs.api-stock.com/en/docs/api/task);
- [генерация изображений](https://docs.api-stock.com/en/docs/guides/image-generation);
- [генерация видео](https://docs.api-stock.com/en/docs/guides/text-to-video);
- [webhook и его ограничения](https://docs.api-stock.com/en/docs/webhooks);
- [срок хранения файлов](https://docs.api-stock.com/en/docs/files).

## Предлагаемая архитектура

1. В `@modern-admin/core` определить независимый от поставщика порт `IMediaGenerationProvider`: получить каталог, создать задачу, проверить статус. Типы результата должны поддерживать `image`, `video`, несколько файлов и произвольный `output`.
2. Создать пакет `@modern-admin/api-stock` с `ApiStockMediaProvider`. Он хранит base URL и ключ только на сервере, вызывает `POST /api/v1/generation/create`, `GET /api/v1/task/status/{taskId}` и валидирует ответы через Zod.
3. Использовать существующий `IAiTaskStore` с отдельным `kind: 'media-generation'`. В задаче хранить локальный UUID v7, `taskId` API Stock, модель, безопасную копию input, пользователя, целевой ресурс/запись/поле и статус импорта.
4. Выполнять отправку, polling и импорт файлов в worker через существующую очередь. Для изображений задать более короткий профиль polling, для видео — длинный timeout и backoff с учётом `Retry-After`.
5. В `@modern-admin/nest` добавить защищённые endpoints каталога, запуска, статуса, отмены локального ожидания и применения результата. Проверять права пользователя на целевой resource action до постановки задачи и повторно перед записью результата.
6. В `@modern-admin/react` добавить диалог `Generate media`: модель, prompt, параметры из схемы каталога, ссылки/референсы, оценка стоимости при наличии данных, прогресс, галерея результатов и кнопка «Применить».

## Сценарий карточки товара

1. Конфигурация feature задаёт поля-источники (`name`, `description`, `category`, `brand`) и целевое поле (`image` или `gallery`).
2. На show/edit-странице действие «Создать карточку товара» собирает только доступные пользователю поля и формирует редактируемый prompt по шаблону.
3. Пользователь выбирает модель изображения и формат, подтверждает платную генерацию, после чего backend создаёт локальную задачу и задачу API Stock.
4. Готовые варианты показываются в preview. Ничего не записывается в товар автоматически.
5. После выбора варианта backend скачивает файл, проверяет MIME/размер, сохраняет его через настроенный upload provider и вызывает обычный edit action Modern Admin. Это сохраняет аудит, permissions, hooks и cache invalidation.
6. Для повторной генерации использовать новый явный запрос; не переотправлять create при проверке статуса, чтобы не получить двойное списание.

## Изображения и видео

- Не фиксировать список моделей в UI: брать его из `GET /api/v1/catalog`, фильтровать по `IMAGE`/`VIDEO` и кешировать с TTL.
- Строить форму параметров из схемы выбранной модели. У разных семейств отличаются `size`, `aspectRatio`, `urls`, `imageUrls` и другие поля, поэтому универсальная жёсткая DTO быстро устареет.
- Поддержать text-to-image, image editing и text/image-to-video одним envelope `{ model, input, webhook? }`.
- Считать `not_started` и `processing` промежуточными состояниями, `finished` и `failed` — терминальными. Обрабатывать все элементы `files[]`, а не только первый.
- Копировать готовые файлы в хранилище проекта: URL API Stock хранится ограниченное время и не должен становиться постоянным CDN URL товара.

## Надёжность и безопасность

- Никогда не возвращать ключ API Stock на frontend и не писать его в task input, логи или события.
- Защитить платный create от двойного клика локальным idempotency key и уникальным ограничением на активный intent. `taskId` сохранять сразу после ответа API.
- Webhook считать только сигналом: он не подписан. Использовать секрет в URL, проверять принадлежность `taskId`, затем заново читать авторитетный статус через API Stock. Обработчик и polling должны быть идемпотентны по `taskId`.
- Добавить лимиты по ролям, моделям, разрешению, длительности, числу файлов и месячному бюджету. Ошибки `4xx` не ретраить; `429`/`5xx` обрабатывать с ограниченным backoff.
- Перед применением результата повторно проверять права и актуальность записи. Для замены существующего файла показывать отдельное подтверждение.

## Этапы внедрения

1. **Основа:** port, API Stock client, Zod-схемы, каталог, create/status, unit-тесты с fake fetch.
2. **Асинхронность:** хранение задач, worker, polling, события прогресса, reconciliation зависших задач.
3. **UI изображений:** общий диалог, preview, импорт в upload provider, ручное применение к записи.
4. **Карточки товаров:** конфигурируемые шаблоны prompt и action для Product, аудит и permission regression tests.
5. **Видео:** video-параметры, большие downloads через streaming, увеличенные timeout/retention alerts.
6. **Webhook:** секретный callback, повторная проверка статуса, идемпотентный общий result handler.
7. **AI-помощник:** добавить tool, который создаёт только черновик/задачу генерации и открывает preview. Применение результата оставить за явным действием пользователя, не ослабляя текущую read-only модель помощника.

## Критерии готовности

- ключ доступен только серверу и маскируется в настройках;
- повторный submit не создаёт вторую платную генерацию;
- задача восстанавливается после рестарта worker;
- webhook и polling приводят к одному результату без дублей;
- все файлы импортируются в управляемое хранилище до истечения внешнего URL;
- применение результата проходит через permissions, audit hooks и cache invalidation;
- сценарии проверены на мобильной ширине, а новые строки переведены во все локали.
